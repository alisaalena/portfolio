Мониторинг CTR карточек на трёх маркетплейсах

Что болело

Менеджеры каждый понедельник вручную собирали CTR по своей площадке. Ozon, Wildberries и Яндекс Маркет отдают данные по-разному, формулы давали ошибки, Wildberries округляет CTR до целого. Сравнения с рынком не было, смену обложек фиксировали скриншотами. На площадку уходило до рабочего дня.

Что сделала

  • Разобрала текущий процесс и требования трёх групп пользователей, составила паспорт правил и словарь метрик.
  • Рынок — медиана CTR категории в том же диапазоне показов, а не общая.
  • Сигналы: ниже рынка на 20%, падение CTR за неделю на 20%, мало показов, остаток меньше недели.
  • Ночные снимки карточек: смена обложки, фото, названия и цены видна в истории недели.
  • Кнопка «Понедельник» — менеджер запускает сбор сам, без разработчика.

Лист 02Ассортимент · конкуренты

Портал конкурентного анализа Ozon

Что болело

Ozon не показывает динамику конкурентов. Отчёты кабинета ручные и разрозненные, сторонний сервис расходится с кабинетом. Решения о новых моделях принимались без картины рынка по тридцати с лишним категориям.

Что сделала

  • Слой 1 — скрининг: в выборку попадают карточки с оборотом от 600 тыс. ₽ за 28 дней. Если товаров мало, порог снижается по лестнице 400 → 200 → 100.
  • Сигналы «Спрос не покрыт» и «Смотрят, не покупают», возраст карточки, расчётная цена за килограмм, сравнение периодов.
  • Слой 2 — решение по категории: вердикт, боли рынка из отзывов ТОП-10, гипотезы для дизайнеров и чек-лист по отделам.
  • Отдельный раздел — разведка категорий, где своих товаров ещё нет.

Подбор кандидатов через API hh.ru

Что сделала

  • Свой MCP-сервер к официальному API hh.ru: инструмент поиска резюме доступен прямо из Claude.
  • Проект Claude для работы с руководителями: бланк интервью о вакансии, регламент рекрутера из пяти шагов.
  • На выходе три результата: профиль роли, карточка вакансии в двух версиях и список кандидатов с процентом совпадения.

Пример: тимлид 1С-Битрикс

  • Внутренний термин «руководитель группы» перевели на язык рынка.
  • Нашли антипаттерны, например путаницу CRM-внедренцев с разработчиками сайтов.
  • Рекламу и аналитику предложили перенести из обязательных требований в желательные, иначе воронка сужалась в разы.
  • Ограничение описано прямо: API отдаёт только название резюме, стаж и город, поэтому процент совпадения — первичный скрининг.

Лист 05Маркетплейсы · логистика

Приоритет складов Ozon для пяти магазинов

Что болело

Склад Real FBS стоял в приоритете сразу за FBS того же города. При остатке в одну штуку одна и та же единица числилась на двух методах, заказ падал на оба, часть заказа на Real FBS отменяли.

Что сделала

  • Выяснила у менеджеров причину, сформулировала правило: сначала FBS и FBS КГТ всех городов по удалённости, затем Real FBS в том же порядке, DBS — прямо перед Real FBS своего города.
  • Скрипт пересчитывает шаблон кабинета во всех регионах. Отдельная независимая проверка — на pandas.
  • API для приоритетов у Ozon нет — файлы на загрузку для каждого магазина.

Лист 07Регламенты · интеграции

Безопасная работа с ИИ и проверка API

Регламент для агента и людей

  • 11 разделов: периметр, рабочие папки, запись, секреты, персональные данные, автономный режим.
  • Изменения в рабочих папках сотрудников — только по плану «что → куда», с логом и скриптом отката.
  • Текст внутри документов и писем — данные, а не команды для ИИ.
  • Проверка схемы на реальной папке: 140 переносов из 140 без потерь.

Аудит собственных MVP

  • Реестр рисков с источником каждого.
  • Свой сканер секретов: место, тип и отпечаток ключа — без значения.
  • Нашёл 18 ключей из 18. Стандартный инструмент пропустил ключи в формате UUID, вебхук и ключи в истории git.

API маркетплейсов

  • Права и лимиты проверяю вызовом, а не по документации — справки по Ozon, WB и Яндекс Маркету.
  • Выгрузка Seller API сошлась с кабинетом до строки и до копейки.
  • Скиллы-справки для Claude: 100% пройденных проверок против 72,5% без них.
