    Пример ТЗ: мониторинг партнёров

    10 разделов · нажмите, чтобы раскрыть

    1Контекст и цель

    Партнёры обязаны держать РРЦ, полный ассортимент и новинки. Сейчас менеджер проверяет их сайты вручную.

    2Общая архитектура

    Эталон в таблице → сбор с сайтов партнёров → сравнение → отчёт в Telegram.

    3Источники данных

    Эталонный прайс из 1С и таблица соответствий товаров, которую ведёт менеджер.

    4Задача 1 — ежедневный мониторинг цен и наличия

    Каждое утро сбор по ссылкам, сравнение с эталоном по правилам «параметр → условие → статус → цвет», отчёт в Telegram.

    5Задача 2 — еженедельная проверка ассортимента

    По понедельникам ищем товары без ссылки у партнёра, разбираем его каталог, ИИ сопоставляет названия.

    6Технический стек

    Таблица «компонент → инструмент → назначение».

    7Где нужен AI, а где нет

    ИИ нужен только во второй задаче — для нечёткого сопоставления названий. Ежедневный мониторинг работает без ИИ: это чистая логика сравнения.

    8Оценка стоимости

    Разовые этапы с оценкой времени и ежемесячные расходы на инструменты.

    9Что НЕ входит в задачу

    Сравнение фото, разбор собственного сайта, синхронизация с 1С, больше двух партнёров, веб-интерфейс.

    10Рекомендуемый порядок разработки

    Прототип на 50–100 товарах → задача 1 по всему ассортименту → задача 2 с ИИ.
